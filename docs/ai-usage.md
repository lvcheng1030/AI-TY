## 三、关键判断与人工修改（这一页最重要）

**1. 为什么不用大模型做意图理解（人工决定，AI 最初建议用）。**
AI 给出的第一版方案是"接云端 ASR + 大模型解析任意说法"。实测延迟约 1.8 秒、需要网络；而作品要在草坪上离线跑 5 分钟，每句话多等 2 秒就毁掉节奏。
人工改为：12 条指令 + 同义词 + 编辑距离 + 三态置信。**"听不懂就说听不懂"比"什么都能听懂但每次等两秒"更适合现场。**

**2. 把"正后方"从机制里删掉（实测驱动）。**
`spike/01` 测出正前与正后不可分辨。AI 曾建议"用双耳时间差区分前后"，但实测数据否掉了这个前提。人工改为前向锥形探测 + 语义播报。

**3. AI 写出了会误伤队友的代码，被人工拦下。**
T7 的第一版 `session.end()` 在改状态之后才取快照，导致用时永远是 0。这个问题是**跑起来**才暴露的（单测断言"用时 41.2 秒"直接抓到），不是读代码看出来的。说明 AI 生成的分支也要有可执行的验收。

**4. 台词模块跨 AudioContext 连接，AI 与原作者都没发现。**
试运行时 3 条任务台词全部静默失败（`InvalidAccessError`）。根因是 `init()` 自建了一个 AudioContext，之后又注入 T1 的 context，`master` 留在旧 context 上。修复方式是"不在 init 自建 context + 换 context 时重建 master"。
**教训：AI 生成的模块单测能过，不代表接线后能跑。**

**5. 人工修掉了 AI 的"过度承诺"。**
早期文案写"能听出精确距离"。T-002 只验证了 2 米与 8 米的差别，人工改成只播"很近 / 有一段 / 很远"三档，并在文档里写明局限。
