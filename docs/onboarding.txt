================================================

一份纯文本指南，可以直接整段复制发到群里。
遇到看不懂的命令，照抄即可；卡住了看第八节。


------------------------------------------------

现在就能做的两件事：
  1. 把 spike 里那两个测试页打开听一下，理解我们在做什么

  2. 认领自己的任务卡，把要改的文件先看一遍


------------------------------------------------
一、准备（每人只做一次，约 15 分钟）
------------------------------------------------

1) 接受仓库邀请

   队长会把你加为协作者。你会收到 GitHub 通知或邮件，点进去接受邀请。
   没收到就把你的 GitHub 用户名发给队长。

   仓库地址：https://github.com/lvcheng1030/AI-TY

   【给队长的一步】
     打开仓库 → Settings → Collaborators → Add people
     → 输入队友的 GitHub 用户名 → 发送邀请
     不加这一步，队友推送会直接 403。


2) 安装 Git

   下载：https://git-scm.com/download/win
   一路点「下一步」即可。

   装完打开 Git Bash 或 PowerShell，输入：
     git --version
   出现版本号就说明装好了。


3) 告诉 Git 你是谁（只做一次）

   git config --global user.name "你的名字"
   git config --global user.email "你的GitHub邮箱"
   git config --global core.quotepath false

   说明：邮箱建议用 GitHub 账号的邮箱，这样提交会关联到你的头像。
   最后一行是让中文文件名正常显示，不加会出现乱码。


4) 把代码下载到电脑

   git clone https://github.com/lvcheng1030/AI-TY.git
   cd AI-TY

   用 HTTPS 不用 SSH。第一次推送时浏览器会自动弹出让你登录 GitHub，
   登录一次以后就不用再管，不需要生成密钥、也不需要配 token。


------------------------------------------------
二、怎么把项目跑起来
------------------------------------------------

项目不需要 npm install，也不需要编译。起一个本地服务器就行：

   python -m http.server 8000

没有 python 就用这个（需要电脑里已装 Node.js）：

   npx --yes serve . -l 8000

然后浏览器打开：

   http://localhost:8000

★★★ 关键：必须用 localhost 打开，不要双击 HTML 文件 ★★★

原因：麦克风权限只在「安全环境」里可用。localhost 算安全环境，
双击打开的 file:// 不算。做语音识别的同学一定会踩这个坑。

（例外：如果只做 T3 文案、T5 音频素材这类不碰麦克风的任务，
双击 HTML 也能看；但只要有一步涉及语音，就必须起服务器。）


------------------------------------------------
三、领任务
------------------------------------------------

全部任务在 docs/tasks.md，一共 10 张卡。

打开后找到标着你名字的那张，卡里已经写清了：
  - 你要改哪些文件（只改这些，别碰别人的）
  - 具体要实现什么功能（细到函数名和行为）
  - 怎么算做完（验收标准，做完逐条勾）
  - 怎么自测
  - 怎么提交（完整命令，照抄即可）

任务卡可以整段复制给 AI，让它帮你写代码。这是刻意的设计。

不会写代码也能领任务：T3（写剧情文案、找音效素材）、
T8（真机测试）、T9（交付材料、现场准备）都不需要编程。


------------------------------------------------
四、日常流程（每次干活都走这五步）
------------------------------------------------

第 1 步：先同步最新代码

   git switch main
   git pull

第 2 步：建自己的分支（分支名任务卡里给了）

   git switch -c feat/t1-audio-engine

第 3 步：写代码，然后提交

   git status                        ← 看看改了哪些文件
   git add 文件名                     ← 或者 git add . 提交全部
   git commit -m "feat(audio): 完成 HRTF 声源池"

   提交信息格式：<类型>: <说明>
   类型只能用这六个：feat / fix / docs / test / chore / spike

   小步多次，别攒一天。评审要看 git log 里的真实开发过程。

第 4 步：推到 GitHub

   git push -u origin feat/t1-audio-engine

第 5 步：开 PR 请求合并

   把下面的分支名换成你自己的，然后浏览器打开：

   https://github.com/lvcheng1030/AI-TY/compare/main...feat/t1-audio-engine?expand=1

   标题写「任务编号 + 名字」，描述里把验收标准逐条勾上。


------------------------------------------------
五、五条硬规矩（保证四个人的代码能合到一起）
------------------------------------------------

1. 零依赖：不许引入任何 npm 包，不许用 CDN。
   现场网络不可靠，而且这是我们定下的技术选型（详见 docs/references.md）。

2. 不许加构建步骤。浏览器直接跑，没有 node_modules。

3. 只改你自己任务卡里列出的文件。别顺手改别人的文件。

4. 不许改 src/core/ 和 content/schema.md。
   这是冻结的接口契约，改了会同时打断所有人。
   确实需要改，先在群里说，由改的人负责通知大家。

5. 不许做需要分辨「正后方」的设计。
   依据：我们实测确认人耳分不出前后（这叫混淆锥），
   已记录在 docs/test-log.md。声源只放在前向半平面。


------------------------------------------------
六、绝对不要提交的东西
------------------------------------------------

  .env、任何密钥、node_modules、超过 5MB 的音频文件

提交前一定先跑一次 git status 看一眼。
把密钥推到公开仓库，等于当场泄露，且历史里删不干净。


------------------------------------------------
七、常用命令对照
------------------------------------------------

  看当前状态             git status
  看改了什么             git diff
  拉取别人的最新代码     git pull
  新建并切到我的分支     git switch -c 分支名
  切回主分支             git switch main
  标记待提交             git add 文件名
  提交                   git commit -m "feat: 说明"
  上传我的分支           git push -u origin 分支名
  看提交历史             git log --oneline
  撤销未提交的改动       git restore 文件名
  撤销已 add 未 commit   git restore --staged 文件名


------------------------------------------------
八、卡住了怎么办
------------------------------------------------

情况 1：push 被拒绝，提示 rejected

  说明远程有别人新提交的代码。执行：

    git pull --rebase origin main

  如果提示冲突，打开冲突文件，找 <<<<<<< 这样的标记，
  把内容改成你想要的样子，删掉那些标记行，然后：

    git add 冲突文件
    git rebase --continue
    git push

  ★ 冲突不要自己乱试。把 git status 的输出贴到群里，一起看。

情况 2：页面打不开、没有声音、麦克风没反应

  先确认是用 http://localhost:8000 打开的，不是双击 HTML 文件。

情况 3：完全不理解报错信息

  把报错整段复制到群里。报错信息里没有隐私，直接贴。

情况 4：卡住超过 1 小时

  在群里说一声。别自己扛一天，这是最浪费时间的做法。


------------------------------------------------
九、每天的节奏
------------------------------------------------

1. 群里发一条：昨天做了什么 / 今天做了什么 / 卡在哪。
   一行就行，不用写长。

2. 提交信息写清楚做了什么。
   不要写「更新」「修改」「fix bug」这类无意义的说明。

3. 分数的一部分就看 git log 和 docs/test-log.md。
   你写的提交信息和测试记录，本身就是得分材料。

4. 测试中发现的问题，写进 docs/test-log.md：
   日期 / 设备 / 测什么 / 结果（带数字）/ 据此改了什么。
   只写「测了，还行」没有价值。
