## T-001 · 空间音频定位测试（相位 A / B）

| 项 | 值 |
| --- | --- |
| 日期 | 2026-11-20 |
| 工具 | `spike/01-audio-localization.html` |
| 设备 / 浏览器 | **待补**（结果页文本里带 UA 与判定） |
| 测试人 / 耳机 | 队长 / **型号待补** |
| 目的 | go / no-go：人耳能否分辨左、前、右；以及前后能否分辨 |

### 结果

| 相位 | 内容 | 结果 |
| --- | --- | --- |
| A | 左 / 前 / 右，各 6 次 | **待补** ← 决定 go/no-go 的关键数据 |
| B | 前 / 后，各 4 次 | **前后区分度不明显**（实测口述） |

### 发现

**前后不可分辨，与预期一致。**

这是 HRTF 的固有局限，不是页面故障。双耳定位依赖时间差（ITD）与强度差（ILD），但在绕两耳轴线的一整圈锥面上这两个值几乎相同——正前方与正后方给出的双耳线索几乎没有区别。人耳平时靠两个额外线索消歧：

1. **耳廓的频谱特征**（pinna notch）——个体差异极大，无法用一套通用 HRTF 覆盖所有人；
2. **头部转动**产生的动态变化。

耳机重放削弱了第 1 条，而测试要求"不要转头"，等于把第 2 条也主动去掉了。所以这个结果既是预期，也是**正确执行测试条件的证明**。

### 据此作出的设计修改（4 条）

1. **正后方不放任何需要分辨的声源。** 声源限制在前向半平面。
2. **敲杖探测改为前向锥形（约 ±45°）。** 只回答"前方有没有东西、多远"，不要求玩家分辨前后——把混淆锥从机制里彻底移除。这与真实盲杖的探测方式也一致。
3. **需要表达"身后"时，改用语义而非空间声像。** 由 AI 助手直说"在你右后方有人"，而不是期待玩家从声像里听出前后。这反而强化了作品主题：**AI 是玩家的眼睛**。
4. **转身升级为核心交互，而不只是移动手段。** 听不准方向时转身再听，是消歧手段。开场教学必须明确教这一条——真实视障者也是靠转动头和身体来定位的。

### 待验证

- **回声延迟能否表达距离**：0.2–1.5 秒区间内人耳能否稳定分辨远近。这是"敲杖"机制成立的前提（机制来源见 `docs/references.md` 中 finding-echo 一条）。

## 记录规范

- 每次真机测试都要写：**日期 / 设备 / 测什么 / 结果 / 据此改了什么**。
- 结果要带数字（准确率、耗时、失败次数），不要只写"感觉还行"。
- 与预期不符的结果优先记录——那是真正改变设计的信号。
