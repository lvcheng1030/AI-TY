## T-002 · 回声距离辨识测试（敲杖机制的前提）

| 项 | 值 |
| --- | --- |
| 日期 | 2026-11-22 13:25 |
| 工具 | `spike/02-echo-distance.html` |
| 设备 / 浏览器 | Edge 158（Chromium 158），Windows |
| 测试人 / 耳机 | 队长 / 型号待补 |
| 距离档位 | 2 米 vs 8 米（延迟 0.16s vs 0.64s，刻意放慢声速） |
| 目的 | 敲杖能否靠"回声"表达距离——T1 敲杖机制成立的前提 |

### 结果

| 分组 | 变化线索 | 正确率 |
| --- | --- | --- |
| 第一组 | **只变延迟** | **6/6（100%）** |
| 第二组 | **只变混响** | **6/6（100%）** |
| 第三组 | 延迟 + 混响 | **6/6（100%）** |
| **合计** | | **18/18（100%）** |

**判定：敲杖机制成立。** 两种线索**各自独立可用**，叠加后依然稳定。

### 结论与设计参数（交给 T1）

**1. 采用延迟 + 混响双线索**（第三组即实际游戏形态）。

**2. 延迟标定：每米约 0.08 秒。**

| 距离 | 回声延迟 | 混响拖尾 |
| --- | --- | --- |
| 2 米 | 0.16 s | 0.25 s |
| 8 米 | 0.64 s | 0.90 s |

**3. 延迟作主线索。** 单线索组两者都是 100%，但延迟实现更稳（不依赖卷积混响质量），
且**近距离响应更快**——2 米只需 0.16 秒，符合"敲一下马上有反馈"的手感。

**4. 回声做成定位声源。** 回声在命中点发声，而不是居中播放。
这样"偏左的障碍物回声偏左"自然成立，玩家能听出障碍在左还是右。
（±45° 锥形内的方位正好落在 T-001 约束的安全区内。）

### 必须记下的两条限制

**限制一：样本小，且只验证了 4 倍差距。**

每组 6 次。6/6 的 95% 置信区间下界约 61%，18/18 约 82%。
更关键的是：测试只对比了 **2 米 vs 8 米**，**没有验证细分辨**（如 3 米 vs 4 米）。

**因此不得对外宣称"能听出精确距离"。** 据此采取的设计：

- 声音层面用连续延迟（免费，且已验证可用）
- **对外播报距离时分档**：近（<3 米）/ 中（3–5 米）/ 远（>5 米）
- AI 助手只说档位，不说"3.7 米"这类未被验证的精度
- 关卡设计上障碍物应分布在不同档位，不依赖玩家分辨相邻的 1 米

**限制二：三组按固定顺序测试，未做顺序平衡。**

理论上存在练习效应（越听越准）。但第一组就已 100%，
说明练习效应即使存在也不是主要因素，**不足以推翻结论**。
若后续需要更精确的测距，再补一轮顺序打乱的测试。

### 据此作出的改进

1. T1 敲杖参数锁定：延迟 0.08 s/米、混响 0.25→0.90 s、前向 ±45° 锥形、最大 8 米。
2. `CaneProbe` 契约新增 `band` 字段（近/中/远），供 AI 助手播报。
3. 新增待办：**细分辨测试（spike 03）**，验证相邻档位（如 3 米 vs 4 米）。
   优先级低于中期交付；但若关卡需要更细的距离表达，必须先测这个。

## T-003 · T2 移动/碰撞/盲道判定的自动化验证

| 项 | 值 |
| --- | --- |
| 日期 | 2026-11-22 |
| 方式 | Node 断言（32 项）+ 无头浏览器端到端（6 个动作） |
| 测试人 | lvcheng1030 |
| 对象 | `src/world/player.js`、`collision.js`、`scene.js` |
| 目的 | 在接真实内容之前，确认移动、碰撞、路面与盲道判定的基础行为正确 |

### 结果

**Node 断言 32/32 通过**（覆盖几何、路面查询、盲道偏离、碰撞边界、移动积分）。

**端到端实测**（沿盲道走、撞自行车、进草地、过拐弯、走出盲道、转身）：

| 动作 | 期望 | 实测 | 结果 |
| --- | --- | --- | --- |
| 沿盲道前进 5 秒 | 前进 6.0 米，路面保持 tactile | `z=6.0`，`tactile` | ✅ |
| 撞上自行车（半径 0.35） | 停在 13.65 | `z=13.65` | ✅ |
| 被阻挡提示的冷却 | 1.2 秒内不重复 | 4 秒内只发 3 次 | ✅ |
| 走进草地 | surface 变为 grass | `grass` | ✅ |
| 盲道拐弯段 (2,25) | 仍判定为 tactile | `tactile` | ✅ |
| 偏离盲道 2 米 | 触发 deviation 提示 | 触发 3 次（6 秒冷却） | ✅ |
| 左转 1 秒（90°/s） | 180° → 90° | `90` | ✅ |

### 发现并修复的问题（3 个真实缺陷）

**1. 贴墙抖动：`intersects` 用了严格小于**

推开函数会把玩家恰好推到「距离 = 半径」的位置，此时严格小于判定因浮点误差仍算作相交，
表现是贴着墙时被反复推来推去。**改为带容差判定**（`< radius - 1e-9`）。

**2. 夹缝卡死：贪心逐个推开会产生震荡**

两个相邻矩形会把玩家往相反方向推，来回震荡后**停在障碍物内部**（实测停在 `x=-0.35`，
仍在障碍物里）。这比抖动更严重——玩家会卡进墙里出不来。

**改为「候选位置法」**：对每个被侵入的矩形生成 4 个单轴推出的候选位置，
丢弃仍然与任何障碍物相交的候选，再从剩下的里选离原始目标最近的。
夹缝中的玩家会被推到「离开整个障碍群最近的那一面」，而不是在两块之间弹。

**3. 起点朝向错误会把人带离路线**

第一次端到端验证时，场景的 `start.heading` 写了 `0`（正北），但盲道向 +z（南）延伸，
结果玩家一起步就往反方向走。

这不是代码 bug，而是**数据约定问题**：`heading` 的语义（0=正北、顺时针为正）容易填错，
而填错的后果是"一开局就走反"。已在 `content/schema.md` 补充醒目提示，
并要求 T3 填完后用「沿盲道走 5 秒仍在盲道上」来验证起点朝向。

### 据此作出的改进

1. 三个碰撞缺陷已修复，回归测试纳入 `tests/world.test.html`（32 项，可随时重跑）。
2. 新增 `CANE_REQUEST` 事件：敲杖拆成「请求 → 探测 → 结果」两步，
   让移动逻辑不必知道音频实现（契约允许新增事件，见 `docs/CONVENTIONS.md`）。
3. 几何与判定全部实现为纯函数，因此可脱离浏览器在 Node 里跑断言——
   这是本项目唯一可行的自动化测试路径（无构建步骤、无测试框架）。
4. `content/schema.md` 补充 `start.heading` 的踩坑提示。

### 待验证

- **回声延迟能否表达距离**：`spike/02-echo-distance.html` 仍未运行。这是 T1 敲杖机制成立的前提。

## T-001 · 空间音频定位测试（相位 A / B）

| 项 | 值 |
| --- | --- |
| 日期 | 2026-11-20 |
| 工具 | `spike/01-audio-localization.html` |
| 设备 / 浏览器 | **待补**（结果页文本里带 UA 与判定） |
| 测试人 / 耳机 | 队长 / **型号待补** |
| 目的 | go / no-go：人耳能否分辨左、前、右；以及前后能否分辨 |

### 结果

| 相位 | 内容 | 结果 |
| --- | --- | --- |
| A | 左 / 前 / 右，各 6 次 | **待补** ← 决定 go/no-go 的关键数据 |
| B | 前 / 后，各 4 次 | **前后区分度不明显**（实测口述） |

### 发现

**前后不可分辨，与预期一致。**

这是 HRTF 的固有局限，不是页面故障。双耳定位依赖时间差（ITD）与强度差（ILD），但在绕两耳轴线的一整圈锥面上这两个值几乎相同——正前方与正后方给出的双耳线索几乎没有区别。人耳平时靠两个额外线索消歧：

1. **耳廓的频谱特征**（pinna notch）——个体差异极大，无法用一套通用 HRTF 覆盖所有人；
2. **头部转动**产生的动态变化。

耳机重放削弱了第 1 条，而测试要求"不要转头"，等于把第 2 条也主动去掉了。所以这个结果既是预期，也是**正确执行测试条件的证明**。

### 据此作出的设计修改（4 条）

1. **正后方不放任何需要分辨的声源。** 声源限制在前向半平面。
2. **敲杖探测改为前向锥形（约 ±45°）。** 只回答"前方有没有东西、多远"，不要求玩家分辨前后——把混淆锥从机制里彻底移除。这与真实盲杖的探测方式也一致。
3. **需要表达"身后"时，改用语义而非空间声像。** 由 AI 助手直说"在你右后方有人"，而不是期待玩家从声像里听出前后。这反而强化了作品主题：**AI 是玩家的眼睛**。
4. **转身升级为核心交互，而不只是移动手段。** 听不准方向时转身再听，是消歧手段。开场教学必须明确教这一条——真实视障者也是靠转动头和身体来定位的。

### 待验证

- **回声延迟能否表达距离**：0.2–1.5 秒区间内人耳能否稳定分辨远近。这是"敲杖"机制成立的前提（机制来源见 `docs/references.md` 中 finding-echo 一条）。
