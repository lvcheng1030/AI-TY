# 作品说明

> 《盲盒校园：暗夜探险》· 纯音频驱动的无障碍主题互动游戏
> 参赛赛道：AI 应用（交互体验 / 无障碍）
> 更新：2026-11-24

## 一、一句话

戴上耳机、屏幕全黑，玩家只能靠听和说走完一段校园路——**你听不见的，就是他们看不见的。**

## 二、要解决的问题

视障学生每天要走的路，是一串只有声音才给得出的信息：盲道在脚下什么质感、车流在左还是右、前面有没有自行车占了道、哪儿有一块牌子。

明眼人靠一眼看完整条路；视障者要靠一根手杖、一双耳朵，一步一步把这条路"问"出来。**这件事很难被讲述，只能被体验。** 所以我们不做科普页，做一段 100 秒的路。

## 四、关键自主设计（这是我们自己做的判断）

**1. 不用大模型做意图理解。**
实测云端意图理解端到端约 1.8 秒且依赖网络。5 分钟一局里每句话多等 2 秒，沉浸感直接归零；游园会草坪还没有可靠 wifi。
换成：12 条指令 + 同义词表 + 编辑距离打分，**三态置信**——高置信直接执行、中置信回述确认、低置信拒答并给示例。把"能听懂任何话"换成"听不懂就说不懂"，这是取舍，不是退步。

**2. 机制里删掉"正后方"。**
`spike/01` 实测：正前与正后给的双耳线索几乎相同（前后混淆锥），通用 HRTF 无法覆盖个体差异。
于是敲杖改成**前向 ±45° 锥形探测**，需要表达"身后"时由 AI 用话说明。这不是绕过难点，是把不可靠的感官换成可靠的语义。

**3. 台词构建期预渲染，运行时零合成。**
27 条固定台词全部离线合成 mp3，运行时只播放；只有"回述确认"这类动态内容才走浏览器 TTS。换来零延迟、断网可用、音色统一。

**4. 键盘永远是主通道，语音是叠加层。**
现场嘈杂、麦克风可能被拒。所有功能都能用键盘 + 按钮面板 + 打字完成，语音失败只会降级，不会卡死。

**5. 屏幕真的全黑。**
游戏屏不放任何装饰性图形（实测 DOM 内 img/svg/canvas 数量为 0）。黑屏是立意，不是没做完。

## 六、主要局限（如实写）

1. **只做了一个场景。** 3 个场景的设计位还在，内容是空的。
2. **语音识别依赖浏览器。** Chrome / Edge 可用；Safari、Firefox 不可用，只能走键盘与面板。
3. **空间音频个体差异大。** 通用 HRTF 对一部分人几乎无效，所以强制 30 秒校准；校准也救不了所有人。
4. **真机覆盖不足。** 目前只在 Windows + Edge 上跑过完整流程；Android / iOS 未测。
5. **没有噪音环境数据。** 食堂、户外的识别成功率还没有测。
6. **评测样本小。** 音频定位测试每组 6 次，结论方向可信，精度不足。

## 七、一句话总结

我们没有让玩家"了解"盲道有多重要，而是让他在黑暗里，靠一根手杖和一双耳朵，走完一段两百米的路。
