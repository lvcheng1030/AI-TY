一、这个压缩包里有什么
------------------------------------------------

本包是项目的**完整 Git 仓库**，不是从工作目录直接打包的文件快照。
解压后目录里包含一个 .git 子目录 —— 全部开发历史都在里面，
可以直接用 git 命令查看每一次提交、每一个改动。

  src/          源代码（原生 ES 模块，无构建步骤，零第三方依赖）
  content/      关卡数据、台词表、意图测试用例
  assets/       音频素材（声景 7 条 + 预渲染台词 27 条，可离线运行）
  tools/        台词预渲染脚本、端到端测试脚本
  tests/        逻辑自测页
  docs/         开发文档、测试记录、调研记录
  materials/    交付截图与材料说明
  spike/        两个技术验证页（可双击直接用浏览器打开）

项目不依赖 npm，也不需要编译。运行方式：

  python -m http.server 8000
  # 浏览器打开 http://localhost:8000/

（必须用 localhost，不能双击 HTML —— 麦克风权限只在安全上下文可用。）

二、怎么核对 Git 记录
------------------------------------------------

解压后在项目根目录执行：

  git log --oneline

应当看到 50 余次提交，最早的提交在 2026-11-20 20:11（仓库初始化）。

还可以看：

  git log --stat                    # 每次提交改了哪些文件
  git shortlog -sne                 # 按作者的提交统计
  git log --graph --oneline --all   # 含分支合并的完整历史

按作者统计提交数（可直接对应成员分工）：

  git shortlog -sne --all

三、这份历史是真实的开发过程
------------------------------------------------

几点说明，便于核验：

1. 仓库于 2026-11-20 初始化，赛前没有任何代码、素材或原型。
   首次提交为 "chore: 初始化仓库（README + 忽略规则）"。

2. 提交是按功能分批的，不是最后一次性导入。可以从历史里看到
   "先跑通 → 发现问题 → 修复 → 再验证" 的完整链路，例如：

     feat(world): 矩形碰撞求解
     fix(audio): 接上脚步声的速度来源（此前 setSpeed 无人调用，脚步从不触发）
     fix(speech): 修复台词跨 AudioContext 连接导致全部静默

3. 文档类提交（docs/test-log.md）记录了每次测试的
   "测了什么 → 发现什么 → 据此改了什么"，与代码提交可以互相印证。

4. 团队使用分支 + Pull Request 协作，每个任务一条分支，合并后保留记录。
   可以用 git log --graph 看到这些合并点。
